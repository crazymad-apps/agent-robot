## 当前偏差

- Demo 使用无鉴权明文 WebSocket，与正式架构要求的 WSS、配对和可撤销设备身份不同。
- Demo 使用裸 PCM 二进制帧，不代表正式 wire layout。
- Demo 使用 `agent-sdk` ephemeral 执行，不具备正式 Runtime Session、审批、持久化和恢复能力。

以上偏差均为明确的阶段性验证选择，不能作为正式产品能力验收证据。

## 2026-08-22 ASR/TTS 实机闭环

Host 使用本地 `.env` 中的 DashScope 密钥，先用 PC 样本验证完整 WebSocket → ASR → TTS → PCM
链路，再进行两次真实设备 PTT。Host 日志只记录字符数、字节数、耗时和请求 ID，不记录密钥或

首次实机结果：


`demo.2` 随即删除整个增益和饱和裁剪分支，不保留兼容开关，改为播放 TTS 原始 PCM 电平。

重新构建、烧录并完成第二次 PTT：

```text

TTS completed: bytes=108948 elapsed_ms=691
```

结论：`demo.2` 的录音、上传、真实 ASR、演示文本、真实 TTS、回传和 I2S 播放均已贯通，无网络、
Provider 或播放错误。移除增益后的链路证据已通过，实际音量是否合适仍以用户听感确认为准。

## 2026-08-22 Agent SDK 首轮闭环

Voice Demo Host 直接链接相邻 ez-assistant 工作树的 `agent-sdk` 和
`agent-openai-compatible`。每轮 ASR 文本构造成单条用户消息，通过
`Agent::start_ephemeral` 执行；Agent 使用空工具集、单模型 step、20 秒超时和独享临时
Recorder，只收集 Assistant 的用户可见 Text Part。超时会取消对应执行，reasoning 不会进入
播报，TTS 文本硬限制为 36 个字符。

PC 使用归档的 5 秒 PCM 样本完成 WebSocket 全链路：


| 2 | 81,920 / 172,948 bytes | 1,660 ms | 1,119 ms | 1,394 ms | 86,474 samples |

20 轮分段耗时统计如下，P95 使用 nearest-rank：

| 阶段 | 平均 | P50 | P95 | 最大 |
|---|---:|---:|---:|---:|

## 2026-08-22 故障恢复

### Host 断线与重连

主动停止 Host 后，终端收到 TCP FIN，进入断开状态并以 3 秒间隔重连；Host 恢复后终端自动连接，
无需复位或重新烧录。恢复后的第 22 轮完整上送 80,896 bytes、接收 88,468 bytes，并播放
44,234 个采样。

### ASR、Agent 与 TTS 失败

- Agent：Host 临时使用明确无效的 LLM 模型名。ASR 成功后 Agent 收到 Provider 404，Host 返回
  `agent_failed`；终端进入错误状态，1 秒后恢复主循环。恢复正常模型后第 24、25 轮均完整播放。
- ASR：PC 客户端在无效 ASR 模型下收到 `asr_failed`，随后收到 `state_changed=idle`。
- TTS：PC 客户端在无效 TTS 模型下依次经过 ASR、Agent、TTS，收到 `tts_failed`，随后收到
  `state_changed=idle`。
- 恢复正常配置后，PC 再次经历 `asr → agent → tts`，声明与实际收到的 TTS 均为 91,016 bytes，
  最终状态为 `idle`。

所有故障注入都只通过当前进程环境覆盖模型名，没有修改 `.env`。普通日志未输出 Key、完整
transcript 或完整回复。
