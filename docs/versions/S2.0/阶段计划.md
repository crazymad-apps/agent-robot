# S2.0 阶段计划

## M1：依赖与版本兼容性

1. 记录当前 ESP-IDF `v6.0.2`、芯片 revision、Flash/PSRAM 和构建产物尺寸。
2. 核对 ESP-SR/ESP-SKAINET 对 ESP32-S3 推荐的 ESP-IDF 范围和组件接入方式。
3. 建立最小 WakeNet 构建探针，只验证依赖、模型选择和链接，不先替换整机入口。
4. 如果官方组件不支持当前 ESP-IDF，先形成升级/降级影响清单，再决定工具链，不静默切换版本。

## M2：Flash、PSRAM 与任务资源规划

1. 读取并保存当前实际分区表、应用二进制尺寸和空闲 Flash 范围。
2. 根据实际选中模型生成模型分区尺寸，不把官方示例的 `6000K` 直接当成固定需求。
3. 保留 NVS、应用、模型和必要诊断空间；确认录音样本分区是否继续保留。
4. 构建后核验分区无重叠，并记录内部堆、PSRAM、关键任务栈和模型运行余量。

## M3：Wi-Fi 配置与安全边界

1. 冻结开发阶段凭据注入方式和 NVS 保存/清除流程。
2. SSID、密码、配对材料和密钥不得进入 Git、固件普通日志、截图或验收文档。
3. 串口日志只允许记录连接状态、受控 SSID 标识、RSSI、IP、重连次数和错误类别。
4. 定义错误密码、AP 不存在、DHCP 超时和恢复出厂配置的可恢复行为。

## M4：唤醒与共存测试设计

1. 记录内置唤醒词、模型版本、阈值、测试距离、房间和背景声条件。
2. 规定 20 次唤醒尝试、至少 18 次成功，以及至少 30 分钟背景声零误触发的原型门槛。
3. 规定 Wi-Fi 断开/恢复、PTT 回退、播放后恢复监听和屏幕状态检查。
4. 原规划 60 分钟全功能长稳及堆、PSRAM、任务栈趋势；2026-08-22 路线复核后延期到 S4.0 PCB 输入冻结前，不再作为阶段二功能验证门槛。

## 停止条件

- ESP-SR 与当前工具链不兼容，且尚未明确工具链变更影响。
- 模型分区与 8 MB Flash 现有数据重叠，或无法留出可解释的安全余量。
- Wi-Fi 凭据需要写入受版本控制文件或普通日志。
- WakeNet 输入要求与已冻结的 16 kHz 单声道 PCM 链路不一致。
- 引入依赖后破坏 S1.4 已通过的屏幕、PTT、收音或放音构建基线。

## 阶段产出

- 一组可重复构建的 ESP-IDF/ESP-SR/模型版本组合。
- 经计算和构建校验的 8 MB Flash 分区方案。
- Wi-Fi 凭据与 NVS 安全方案。
- 可执行的 S2.1～S2.3 功能测试矩阵和停止条件；严格可靠性项延期到 S4.0。
