# S3.0 阶段计划

## 范围边界

- 本阶段只回答 Demo 链路是否可行，不冻结正式进程拓扑和设备协议。
- S3 终端从空工程开始，仅实现本阶段链路；不为 S1/S2 Demo 保留兼容代码。
- 原 S1/S2 工程冻结到 `demos/S2.3/`，只保留为阶段证据和必要时的人工参考。
- 不修改 ez-assistant Runtime Host，不把 Demo Host 作为第二个正式 Host。
- 不做 token、设备配对、证书、持久 Session、审批、多设备、Opus、AEC 或播放中唤醒。
- Provider 凭据只存在于 PC 本地配置或环境，不进入固件、仓库和普通日志。

## 执行顺序

### demo.1：媒体通信

1. 建立无鉴权 WebSocket 连接和最小 JSON 控制消息。
2. PTT 按下发送 `listen_start`，随后以二进制帧发送裸 PCM。
3. PTT 松开发送 `listen_stop`，Host 把已收音频原样回传。
4. 终端按 `playback_start` / 二进制 PCM / `playback_end` 播放并回到空闲状态。
5. 验证连接中断、无活动话语时收到 PCM、话语 ID 不匹配和大小超限的明确错误。

### demo.2：ASR/TTS 闭环

1. 抽象整句 ASR 和可取消 TTS 接口，先各装配一个真实实现。
2. 将完整 PCM 话语交给 ASR，向终端返回 transcript。
3. 先用固定回复或 transcript 回显驱动 TTS，统一输出为 PCM16/16 kHz/mono。
4. 记录 ASR 总耗时、TTS 首包/总耗时、播放 underrun 和失败原因。

### demo.3：Agent SDK 闭环

1. 通过本地路径引用 ez-assistant `agent-sdk`，记录实际 commit 作为可复现输入。
2. 使用 `Agent::start_ephemeral` 处理 ASR 文本，不建立正式 Session/Run/Journal。
3. 收集面向用户的回复文本，分段交给 TTS 并支持取消当前播放。
4. 连续完成至少 20 轮 PTT 对话，记录各段延迟与失败。

## 每个里程碑的停止条件

- 音频帧或网络处理阻塞终端 I2S 关键路径。
- 收到的 PCM 格式、长度或话语边界与声明不一致。
- 断线或重试造成同一句被重复送入 ASR 或 Agent。
- Demo 日志包含完整语音、完整 transcript、模型凭据或其他敏感内容。
- ez-assistant 当前变更使本地路径依赖无法稳定构建；此时停止 Agent 接入，不复制 SDK 实现。

## S3.0 阶段门

- 终端与 Demo Host 完成双向 PCM 媒体通信。
- 一段真实人声能够得到可理解 transcript，并能播放清晰 TTS。
- `agent-sdk` 临时执行入口完成至少 20 轮 PTT 语音对话。
- 连接、ASR、Agent 和 TTS 错误均能明确恢复到可再次 PTT 的状态。
- 形成供正式联合设计使用的延迟、缓冲、协议和故障记录。
