# Agent 硬件终端（agent-robot）架构设计

## 0. 方案选型（已更新：ESP32 路线）

**结论：终端采用 ESP32-S3 系列 + ESP-IDF 框架，取代 Linux 单板方案。**

| 对比项 | 树莓派方案（弃） | ESP32 方案（采用） |
|---|---|---|
| 系统 | Linux + 音频/图形栈 | 裸机/RTOS，上电即跑 |
| 成本 | ¥300+ 外接屏麦喇叭 | 开发板 ¥40~150，全集成 |
| 音频 | USB 声卡 | I2S 数字音频直连 |
| 唤醒词 | 自集成第三方 | 官方免费 ESP-SR 离线唤醒 |
| 显示 | 重量级 GUI | LVGL 小屏 或 内置 Web 页面 |
| 功耗体积 | 大 | 小，可电池供电 |

**推荐硬件（二选一）**：
- A. `ESP32-S3-BOX-3`：双麦 + 喇叭 + 2.4" 触摸屏 + WiFi 全集成，零焊接，官方 AI 语音终端开发板。
- B. 自拼：ESP32-S3 + INMP441(麦) + MAX98357A(功放) + ST7789(屏) 或不做屏改用 Web 页面。

**软件框架**：ESP-IDF + esp-adf(音频) + esp-sr(唤醒词) + LVGL(显示) / 内置 Web Server。

## 1. 项目定位

软硬件结合项目，实现一个 **Agent 硬件终端**：

- **Agent 本体运行在远端**（remote），负责智能对话、推理、工具调用等核心逻辑。
- **本终端 = UI 层 + 操作层**：负责本地感知（监听）、输出（发声、显示）、交互控制。

```
┌───────────────────────────┐        ┌───────────────────────────┐
│   终端硬件（本项目）         │        │   远端 Agent 服务          │
│                           │        │                           │
│  ┌─────────────────────┐  │  信令  │  ┌─────────────────────┐  │
│  │ UI 层（显示/状态/交互）│◄─┼────────┼─►│ Agent 核心逻辑        │  │
│  └─────────────────────┘  │        │  └─────────────────────┘  │
│  ┌─────────────────────┐  │ 音频流 │  ┌─────────────────────┐  │
│  │ 操作层（监听/发声/按键）│◄─┼────────┼─►│ 语音/LLM 服务        │  │
│  └─────────────────────┘  │        │  └─────────────────────┘  │
└───────────────────────────┘        └───────────────────────────┘
```

## 2. 终端四大能力（ESP32 落地）

| 能力 | 方向 | ESP32 实现 |
|------|------|-----------|
| 监听 Listen | 输入 | I2S 麦克风（INMP441/BOX 双麦）→ 16kHz 16bit PCM → WS 上送 |
| 唤醒 Wake | 输入 | ESP-SR WakeNet 离线唤醒词，唤醒后进入监听 |
| 发声 Speak | 输出 | 接收远端音频帧 → I2S → 功放/喇叭（MAX98357A/BOX 自带） |
| 显示 Display | 输出 | LVGL 小屏（状态/文本/动画）或 ESP32 内置 Web 页面 |
| 交互 Operate | 双向 | 触摸/按键/唤醒词 控制会话状态 |

## 3. 通信模型（建议）

- **控制/信令**：WebSocket（双向、低延迟、易扩展），承载事件与 JSON 消息。
- **音频流**：优先 WebSocket 二进制帧（Opus/PCM），避免二次连接；备选 RTP。
- **心跳/重连**：心跳保活 + 指数退避重连 + 断网状态上屏。

## 4. 待确认的选型问题（剩余非阻塞项）

1. **硬件**：ESP32-S3-BOX-3（推荐）还是自拼板（INMP441+MAX98357A+ST7789）？
2. **显示**：LVGL 小屏，还是 ESP32 内置 Web 页面（手机/浏览器查看）？
3. **远端 Agent 协议**：自研 WebSocket 协议 / 对接现成 API（如 OpenAI 兼容）？
4. **唤醒词**：先用官方内置唤醒词（"Hi ESP"等），还是训练自定义词（"你好小乐"）？

## 5. 后续里程碑（选型确认后细化）

- M0 项目骨架：目录结构、配置、日志、依赖管理
- M1 音频通路：采集 → 上送 → 接收 → 播放
- M2 信令通路：WebSocket 连接、会话生命周期、心跳重连
- M3 显示 UI：状态机 + 对话界面
- M4 联调与打磨：唤醒、降噪、低延迟、异常恢复
