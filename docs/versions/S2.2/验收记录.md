# S2.2 验收记录

> 状态：已完成；第二轮唤醒率、PTT 回退和 40 分钟误触发观察均通过。

| 项目 | 当前证据 | 状态 |
|---|---|---|
| 模型与版本 | `esp-sr 2.4.7`、`wn9_nihaoxiaozhi_tts` 已在 S2.0 冻结 | 通过（前置） |
| AFE/WakeNet 构建 | `S2.2-wake.1` 在 ESP-IDF v6.0.2 + esp-sr 2.4.7 下构建、链接及冻结检查通过 | 通过（构建） |
| 应用尺寸 | `0x16bd80` / `0x200000`，余 `0x94280`（29%） | 通过（构建） |
| 烧录 | bootloader、partition table、model、app 四段均通过 esptool 写后 hash 校验；NVS 未擦除 | 通过 |
| 实机模型加载 | `wn9_nihaoxiaozhi_tts` 加载成功；AFE `1MIC_V251128`，流水线仅 WakeNet | 通过 |
| AFE 输入参数 | 单麦、16 kHz、feed chunk 512、1 channel，与 INMP441 基线一致 | 通过 |
| Wi-Fi 冷启动共存 | 从 NVS 自动恢复 `192.168.31.135`，RSSI -28 dBm，重连计数 0 | 通过（首次启动） |
| 持续单麦监听 | 已持续进入 `WAKE READY`；所有已记录闭环结束后均恢复监听 | 通过（短时） |
| 唤醒本地闭环 | 命中时均为 `model_index=1/word_index=1`；每次均完成提示、5 秒录音回放并回到 `WAKE READY` | 通过（短时） |
| PTT 回退 | GPIO21 明确记录 `PTT trigger`，完成 5 秒录音、回放并恢复 `WAKE READY` | 通过 |
| 20 次唤醒统计 | 首轮统一测试记录 17 次成功、3 次漏检，成功率 85%；未达到不少于 18/20 的阶段门 | 未通过（首轮） |
| 固定 0.5 米复测 | 第二轮 20 次为 18 次成功、2 次漏检，成功率 90%；成功命中记录为 `count=19..36`，每轮均恢复 `WAKE READY` | 通过（18/20） |
| 额外触发 | 串口在最后一批 4 次人工尝试期间记录了 5 次命中；用户可能在录音期间再说过唤醒词，时点无法还原，暂记为来源不确定，不计入 20 次成功率 | 待专项观察 |
| 30 分钟误触发观察 | 专项观察 40 分钟，用户未观察到自行录音/回放；串口期间无新增 `DETECTED`、PTT、错误或重启输出，观察基线计数为 36 | 通过（40 分钟） |

## 当前结论

- WakeNet 链路和本地闭环已可重复运行；固定 0.5 米、统一发音节奏的第二轮为 18/20（90%），达到唤醒率阶段门。
- 首轮 17/20 与第二轮 18/20 的差异表明当前默认模型对距离和发音一致性有可见敏感性；不因单轮通过而删除首轮结果。
- PTT 回退和 40 分钟误触发专项观察均通过；S2.2 阶段门通过，允许进入 S2.3 联网、唤醒与媒体共存验证。
