# Agent 硬件终端：硬件架构设计

> **文档状态：当前硬件架构基线。**
>
> 本文定义硬件职责、接口、电源与迁移约束。具体模块商家、屏幕排针顺序、麦克风最终料号和
> PCB 封装必须在实施路线对应阶段完成实测后冻结，不能仅凭候选型号直接进入打板。

## 1. 设计目标

硬件终端只承担人机交互，不运行 Agent 本体：

- 采集单路语音。
- 播放语音回复。
- 显示连接和对话状态。
- 接收 PTT、滚轮和确认/返回输入。
- 通过 Wi-Fi 与语音接入层通信。

架构需要同时支持两个形态：

1. **飞线原型**：使用 ESP32-S3 开发板和分体模块验证功能。
2. **集成整机**：保持相同逻辑接口，迁移到 ESP32-S3 模组、自绘 PCB 和定制外壳。

## 2. 范围边界

### 2.1 核心整机包含

- USB 供电。
- 单个数字麦克风。
- 单声道功放和喇叭。
- SPI 彩屏；飞线基线为 240×240 ST7789，最终物理尺寸和模组在 S4.0 按产品比例冻结。
- 独立 PTT、三脚增量滚轮和独立确认/返回键。
- 独立硬件电源开关；具体电源切断方案在 S4.0/S4.1 随电源树设计。
- Wi-Fi、状态显示和基础诊断。

当前飞线原型只装配 GPIO21 PTT。S3.3 使用可靠转接板或焊盘验证滚轮 A/B 相和确认/返回键；
最终器件、位置、固定方式及硬件电源开关在 S4.0 冻结，不把未验证候选写成现状。

### 2.2 首版不包含

- 电池、充电、电源路径和低功耗待机。
- 双麦、波束成形和声学回声消除。
- 自定义唤醒词量产模型、播放期间唤醒和免唤醒持续对话。
- 摄像头、移动底盘和执行机构。
- 触摸屏、灯环和环境传感器。

这些能力不能影响首板的尺寸、电源和接口；只有后续版本确认后才进入扩展设计。

## 3. 逻辑架构

```text
                         ┌──────────────────────┐
                         │  ESP32-S3 主控       │
                         │  Wi-Fi / FreeRTOS    │
                         │  音频缓冲 / UI 状态  │
                         └───┬─────┬─────┬──────┘
                             │     │     │
                I2S 全双工 ──┘     │     └── GPIO ── PTT / 滚轮 / 确认返回
                    │               │
          ┌─────────┴────────┐      └── SPI ── ST7789 显示屏
          │                  │
   数字 MEMS 麦克风     I2S Class-D 功放 ── 喇叭

   USB 5V ──┬── 开发板/PCB 3.3V 电源 ── 主控、麦克风、显示逻辑
            └── 5V 功放支路 ──────────── 功放与喇叭
```

## 4. 核心器件与接口决策

| 模块 | 架构决策 | 冻结时点 |
|---|---|---|
| 主控 | ESP32-S3-WROOM-1-N8R8；原型使用官方 ESP32-S3-DevKitC-1 v1.1 | 原型板实物已核对，PCB 器件在 S4.0 复核 |
| 麦克风 | 3.3V、标准 I2S、单声道数字 MEMS；最终料号需为可采购的在产器件 | 阶段一 S1.0/S1.3 |
| 音频输出 | MAX98357A 类 I2S 单声道 Class-D 功放，带硬件使能 | 阶段一 S1.1 |
| 喇叭 | 与实测功放供电和箱体匹配，不以模块宣传功率作为设计值 | 阶段一 S1.1，外壳定型前复核 |
| 显示 | 飞线基线为 ST7789 240×240 四线 SPI；产品屏幕尺寸、模组外形和背光控制按 UI 与整机比例重选/复核 | 飞线屏已在 S1.2 验证；产品屏在 S4.0 冻结 |
| 本地输入 | 独立低有效 PTT；三脚机械增量滚轮使用 A/B 两相；另设低有效确认/返回键，全部上拉并软件消抖 | PTT 已在 S1.4 验证；滚轮与确认键在 S3.3 验证，器件在 S4.0 冻结 |
| 电源开关 | 位于顶部或底部的独立硬件开关；必须作用于电源路径，不能用普通 GPIO 假装彻底关机 | 位置与电气方案在 S4.0/S4.1 冻结 |
| 网络 | 2.4GHz Wi-Fi；BLE 不进入首版功能 | 阶段二 |

麦克风飞线模块与 PCB 最终器件是两个决策。原型允许使用可获得的兼容模块，但 S4.0 必须重新核对
器件生命周期、封装、灵敏度、时钟格式和供货状态。

## 5. 音频架构

### 5.1 总线

- 使用一个 I2S 控制器的标准模式全双工收发。
- RX 与 TX 共享 BCLK 和 WS，分别使用独立 DIN、DOUT。
- TX/RX 必须使用相同采样率、时钟极性和每帧总位数。
- 麦克风输入保持 32-bit slot，固件显式完成有效位提取、增益和 PCM16 转换。
- 功放输出只播放语音，不以音乐保真作为首版目标。

### 5.2 统一音频格式

首版内部和网络边界统一为：

| 参数 | 值 |
|---|---|
| 采样率 | 16 kHz |
| 量化 | signed PCM 16-bit little-endian |
| 声道 | mono |
| 网络帧 | 20 ms，320 samples，640 bytes payload |

I2S 驱动可以使用更宽 slot，但进入网络和应用层前必须转换为上述格式。语音接入层负责把不同 TTS
输出重采样为该格式，终端不承担通用音频格式兼容。

### 5.3 并发与声学边界

- 硬件和驱动允许收发通道并存，但首版交互采用半双工：监听时不播放，播放时不持续上传麦克风。
- 播放期间按下 PTT 先触发停止播放，再进入新一轮监听。
- 首版不承诺免唤醒打断，不需要 AEC 播放参考通道。
- 麦克风与喇叭在飞线和外壳中均需物理隔离，避免结构振动直接耦合。

## 6. 原型 GPIO 规划

以下分配包含已验证的 DevKitC-1 v1.1 N8R8 飞线基线和 S3.3 待验证候选；接线前必须结合板卡
原理图和模块实物继续复核。

| 功能 | GPIO | 说明 |
|---|---:|---|
| I2S BCLK | 4 | 麦克风与功放共享 |
| I2S WS | 5 | 麦克风与功放共享 |
| I2S RX / 麦克风 SD | 6 | 主控输入 |
| I2S TX / 功放 DIN | 15 | 主控输出 |
| 功放使能 | 16 | 启动时默认关闭，播放前开启 |
| SPI SCLK | 12 | 显示屏 |
| SPI MOSI | 11 | 显示屏 |
| 显示 CS | 10 | 若模块未引出 CS，需记录实际接法 |
| 显示 DC | 9 | 显示屏 |
| 显示 RST | 8 | 显示屏 |
| 显示背光 PWM | 7 | 不直接用 GPIO 驱动超出能力的背光负载 |
| PTT | 21 | 已验证，低有效；保持独立且交互优先级最高 |
| 滚轮 A 相 | 1 | S3.3 候选，内部上拉，公共脚接 GND |
| 滚轮 B 相 | 2 | S3.3 候选，内部上拉，公共脚接 GND |
| 确认/返回键 | 14 | S3.3 候选，低有效；需先复核开发板与启动电平 |

约束：

- GPIO0 保留给 Boot，不作为产品按键。
- GPIO19/20 保留 USB D-/D+。
- GPIO35/36/37 在 N8R8 模组上用于内部 Flash/PSRAM 通信，不使用。
- GPIO45/46 等启动配置引脚不接用户交互。
- GPIO38 连接 DevKitC-1 v1.1 板载 RGB LED，不用于外接模块。
- 所有引脚集中在一份固件 board config 中，不散落到驱动实现。
- 三脚滚轮只提供 A/B 相旋转输入，不包含按压触点；确认/返回使用独立按键，因此不增加滚轮引脚数。
- GPIO 候选只在 S3.3 飞线/转接验证通过后进入 PCB 输入，不能仅凭当前未占用状态直接冻结。

## 7. 电源架构

### 7.1 飞线阶段

```text
USB 5V
├── DevKitC-1 板载稳压 ── 3.3V：主控、麦克风、显示逻辑
└── 5V/VBUS ───────────── 功放电源
```

- 所有模块共地。
- 功放支路靠近模块放置本地去耦和足够的储能电容。
- 先分别测量主控、屏幕、录音和最大目标音量下的电流，再决定是否可继续使用开发板电源支路。
- 不把面包板和杜邦线的稳定表现直接视为 PCB 电源设计证据。

### 7.2 首版 PCB

- USB-C 仅作为 5V Device 电源与固件下载接口。
- 硬件电源开关需要切断整机目标电源路径；仅让 ESP32 读取一个 GPIO 不能在 USB 仍供电时实现真正关机。
- 5V 分为功放支路和逻辑稳压输入支路。
- 3.3V 稳压器额定能力不低于 1A，并根据热耗散、瞬态和实测峰值留余量。
- 主电源入口加入 ESD、保险/限流评估和至少 10µF 储能；每个 IC 按数据手册就近去耦。
- 功放电源与数字/射频电源分路布置，保持完整地平面并控制大电流回路。
- 首板不加入 18650、TP4056 或其他电池电路；电池作为独立版本重新设计。

## 8. PCB 迁移架构

从 DevKitC-1 迁移到 WROOM 模组时必须补齐开发板隐藏的基础设施：

- EN、Boot、复位与下载电路。
- USB D+/D-、USB-C CC 电阻、ESD 与接口布局。
- UART 下载/诊断测试点。
- 3.3V 电源、去耦和上电时序。
- 模组天线净空、板边位置和禁布区。
- 显示、麦克风、功放、按键和扬声器的可测接口。
- 关键电源、I2S、SPI、EN、Boot 和 UART 测试点。

首板优先可调试性，不追求最小尺寸，也不沿用 DevKitC 板框。PCB 外形应围绕最终屏幕可视区、
左侧滚轮、正面确认/返回键、右侧 PTT、顶部或底部电源开关、声学空间和天线净空形成；屏幕不应
为了适配开发板尺寸被迫缩小。难以返修的器件、底部拾音麦克风和机械接口需要在下单前进行封装与
实物尺寸复核。

## 9. 机械与声学接口

硬件架构向外壳支线提供以下冻结信息：

- PCB 外形、安装孔和器件最大高度。
- 屏幕可视区、排线/排针方向和视角。
- 左侧滚轮、正面确认/返回键、右侧 PTT、顶部或底部电源开关、USB 和调试口的可达空间。
- 麦克风声孔位置、密封方式和禁挡区域。
- 喇叭尺寸、固定方式、出声方向和音腔需求。
- 天线净空区内不得放置金属件、喇叭磁体和密集线束。

阶段一至三只能探索外观、人机工学与声学方向；Blender 示意模型不是尺寸真值。PCB S4.0 使用
最终屏幕和控件实物尺寸完成上述冻结后，外壳才能进入精确结构设计。

## 10. 固件可诊断要求

每个硬件能力都必须提供独立诊断入口：

- 显示色条、背光和刷新测试。
- 麦克风峰值、RMS、削波计数和固定时长录音。
- 功放测试音、静音和缓冲 underrun 计数。
- 按键原始电平、消抖后事件和长按测试。
- Wi-Fi RSSI、重连次数和当前网络状态。
- 启动原因、剩余堆内存和关键任务水位。

诊断信息只通过串口或受控调试界面输出，不记录用户完整语音正文。

## 11. 冻结点

| 冻结点 | 必须确认的内容 |
|---|---|
| S1.0 | 开发板与模块准确版本、供电电压、引脚、ESP-IDF 版本 |
| S1.1 | 功放供电、喇叭阻抗、目标音量、电流和失真 |
| S1.3 | 麦克风格式、有效位、增益、底噪和可用性 |
| S1.4 | 整机 GPIO、音频格式、缓冲规模、连接器方向 |
| S2.0 | ESP-SR/ESP-IDF 兼容组合、模型分区、Wi-Fi 凭据边界和测试条件 |
| S2.3 | Wi-Fi 重连、WakeNet 输入与媒体的最小功能共存边界 |
| S3.2 | GPIO、音频、显示、功放、供电和 ESP32 资源假设的架构 Review；不在本阶段冻结新器件或 PCB 尺寸 |
| S3.3 | 滚轮 A/B 相、确认/返回键、PTT 优先级、候选 GPIO 和屏幕交互可用性 |
| S3.4 | Agent 双入口交互、网络负载、协议版本和故障恢复基线 |
| S4.0 | WakeNet 阈值、资源趋势、长时运行、网络/供电故障、峰值功耗，以及 PCB 最终器件、封装、屏幕、外形、安装孔、电源和机械接口 |
