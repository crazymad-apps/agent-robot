# S3.1 断线重连设计

## 1. 目标

断线重连必须同时满足：

- AP、Host、mDNS、TCP、TLS、WSS 或认证链任一临时中断后能自动恢复；
- 重连不会形成高频循环、重复提交同一句话或重播已经开始的回复；
- 证书、身份和协议错误不会被当作普通网络故障无限重试；
- 网络恢复不能阻塞 I2S、LVGL 或导致终端通过自动重启掩盖问题。

S3.1 不实现断线后的 Conversation 回填。Runtime 仍是 Session、Run 和幂等的权威来源；终端只恢复
连接、当前未确认话语和本地交互状态。

## 2. 两层恢复边界

```text
Wi-Fi Supervisor
  disconnected → connecting → got_ip
                              │
                              ▼
Device Connection Supervisor
  discovering → tcp_tls → wss → pairing/auth → online
       ▲                                      │
       └──────── backoff / rediscover ────────┘
```

### 2.1 Wi-Fi 层

- 沿用 S2.3 已验证的 1/2/4/8/16/30 秒退避和 NVS 凭据恢复。
- `WIFI_EVENT_STA_DISCONNECTED` 后立即关闭 socket、停止 Device WSS 计时器并作废发现结果。
- Device WSS 不参与 Wi-Fi connect，不在没有 IP 时启动自己的重连计时器。
- `IP_EVENT_STA_GOT_IP` 后才启动新一轮 mDNS；IP 改变视为新的连接 epoch。
- 普通网络故障不得调用 `esp_restart()`；看门狗只处理真正的任务失活。

### 2.2 Device WSS 层

- 非安全类失败按 1/2/4/8/15 秒退避，加入 ±20% 随机 jitter；首次失败也至少等待约 1 秒。
- 连续在线并通过 heartbeat 60 秒后，失败计数归零。
- 每次失败都重新确认 Wi-Fi/IP；有 IP 时使缓存 endpoint 最多重试一次，仍失败则重新 mDNS 查询。
- Host 地址或端口变化时，只接受相同 `installation_id` 和已保存 certificate pin 的实例。
- 退避期间新 mDNS 结果或 `GOT_IP` 事件可以提前唤醒，但同一时刻只能有一个连接尝试。

退避使用 monotonic clock；系统时间未同步不能影响重连。设备长期离线时在 15 秒上限持续尝试，
不会因达到固定次数永久放弃。

## 3. 连接状态机

```text
WIFI_DOWN
   │ got_ip
   ▼
DISCOVERING ── compatible host ──▶ CONNECTING
    ▲                                  │ TCP/TLS/WSS ready
    │                                  ▼
BACKOFF ◀── transient failure ── AUTHENTICATING ──▶ ONLINE
    ▲                                  │
    │                                  ├─ transient failure → BACKOFF
    │                                  └─ security/identity failure → BLOCKED
    │
    └──────── ONLINE link lost
```

`BLOCKED` 不是普通断线：必须等待外部条件变化或用户操作，不能按 1/2/4/8/15 秒循环攻击 Host。

### 3.1 单次连接时限

| 步骤 | 时限 | 超时动作 |
|---|---:|---|
| mDNS 查询 | 5 秒 | 进入 Device backoff 后重新查询 |
| TCP connect | 5 秒 | 关闭 socket，重新发现 |
| TLS handshake + pin | 10 秒 | 超时退避；pin 不匹配进入 `BLOCKED` |
| WebSocket Upgrade | 10 秒 | 关闭并重新发现 |
| pairing/auth 应用握手 | 30 秒 | 保留合法 pairing/pending 上下文后退避 |
| online 无任何入站数据 | 30 秒 | 主动关闭，reason=`heartbeat_timeout` |

Host 当前每 15 秒发送应用层 `ping`，25 秒未收到设备数据会关闭连接。设备收到应用 `ping` 后立即回
同 payload 的 `pong`；任何合法 text/binary/Ping/Pong frame 都刷新本地 `last_rx`。

## 4. 连接 epoch 与陈旧数据隔离

每次取得新 IP 或开始新 WSS 连接时递增 RAM 中的 `connection_epoch`：

- Network、Controller、capture/playback 之间的控制事件均携带 epoch；旧 epoch 事件直接丢弃。
- 新连接重新生成 connection 内的 message ID、stream ID 和 sequence；不得复用旧 stream ID。
- 断线立即清空网络 TX/RX 队列、旧 control reassembly 和下行 PCM 队列。
- I2S capture cache 不随网络队列清空；它由 `client_input_id` 恢复规则单独管理。
- 旧 socket 回调晚到时只能关闭旧资源，不能修改新连接状态。

Connection Supervisor 是 socket 与 epoch 的唯一所有者；Controller 是交互状态的唯一写入者。

## 5. Host 发现恢复

### 5.1 已配对设备

1. 查询 `_ez-assistant._tcp.local.`。
2. 只选择保存的 `installation_id`。
3. TXT protocol major、path 和 certificate fingerprint 必须与本地身份兼容。
4. 连接后仍以 peer DER SHA-256 作为最终 pin；mDNS TXT 不能替代 TLS 证书读取。

若相同 installation 的地址或端口改变，可以自动连接；若 fingerprint 改变，进入
`BLOCKED/CERT_CHANGED`，绝不自动信任新证书。

### 5.2 未配对设备

- 开机立即扫描；无开放 Host 时按 2/4/8/10 秒退避并持续查询。
- 多 Host 中只有一个 `pairing_available=true` 时自动选择它；两个以上开放时保持发现并显示
  `MULTIPLE HOSTS`，不随机选择或使用 PTT 循环选择。
- 用户通过 Desktop 只打开目标 Host 的 pairing window 来完成 Host 选择；设备端无需配对按键。
- pairing 中断且窗口未过期时，RAM 中保留同一 pairing request ID、配对码、nonce、scalar 和 share，
  重连后重发同一 `pairing_hello`；不能每次断线生成新码造成 Desktop 上出现多个 pending 请求。
- 单纯 WSS 短断线且同一 pairing window/attempt 仍有效时，重发同一 `pairing_hello`，避免 Desktop
  pending request 改变。
- pairing window 到期/关闭或确认 Host 进程重启后，清零旧 PAKE 临时 secret 并生成全新的 request
  ID、nonce、scalar 和 share，但继续使用本次设备启动会话的同一个 6 位显示码。
- 已写入 pending credential 时，重连优先尝试该身份认证；成功后激活，认证失败才安全清除 pending
  并回到配对。
- 只有设备重启、显式配对重置、配对成功或累计达到 5 次安全失败时才使显示码失效。失败计数绑定
  当前显示码保存在设备 RAM，Host/WSS/window 重启不清零；达到阈值时立即轮换新码和全部临时量。
- active identity 需要重置时，上电前长按 GPIO21 8 秒，出现 `RELEASE TO RESET` 后释放才清除配对；
  一直低电平不执行清除。该操作保留 Wi-Fi，完整恢复出厂仍走串口确认命令。

## 6. 对话阶段恢复

语音上行有两个不同确认边界：`input_segment_accepted` 表示 Host 已完整接管一段 canonical PCM，
终端收到后立即释放该段缓存并允许下一次 PTT；`input_accepted` 只表示 Host 已把一个或多个分段合并为
单个 Runtime Input。二者不得互相替代。

若 Host 在接管 PCM 前拒绝分段，终端释放对应 canonical PCM；若 ASR 或 Runtime 提交在
`input_segment_accepted` 后失败，终端已经没有该段缓存，只根据 `idle` 回到可录音状态。两种结束语义
都不发送多余的 `listen_cancel`。

| 断线时阶段 | 本地动作 | 重连后动作 |
|---|---|---|
| idle | 清网络队列，显示 `CONNECTING` | 认证成功回 `READY` |
| listening，PTT 未松开 | 继续收音到 PSRAM，不继续旧 socket 发送 | 等 PTT 松开形成固定话语，再完整发送 |
| listening，PTT 已松开 | 封口 canonical PCM，冻结 ID 与 preference | 同一 `client_input_id`、新 stream ID、sequence 0 完整重传 |
| stop 已发送，未收到 `input_segment_accepted` | 保留完全相同的 PCM/ID/preference | 完整重传该分段 |
| 已收到 `input_segment_accepted`、未收到最终 `input_accepted` | 已释放该段 PCM，显示 `THINKING` | Host 按 device ID 保留聚合和 ASR 任务；新 WSS 继续同一逻辑轮次 |
| 已收到 `input_accepted` / processing | 保留“整轮已接受”事实到本轮结束 | 不重提、不请求历史回填；等待未来实时输出或回 `READY` |
| speaking | 立即关闭功放、清下行 PCM 队列 | 不重播；认证成功后等待新实时事件或回 `READY` |
| needs_attention | 不重提已接受输入 | 回 `CHECK DESKTOP` 或 `READY`，审批仍由 Desktop 处理 |

### 6.1 canonical 话语约束

- `client_input_id`、最终补零后的 PCM bytes 和 `output_preference` 在首次 `listen_stop` 前冻结。
- 每次重传可使用新的 stream ID/message ID，但 PCM bytes 与 preference 必须逐字节相同，否则 Host 会
  正确判定为 `client_input_reused`。
- 网络断开时不边追帧边恢复旧流；继续本地收音，待 PTT 松开后一次性从 sequence 0 发送，减少双游标
  和乱序风险。
- 话语最长 60 秒。PTT 松开后等待重传最多 120 秒；超时清除 cache 并显示 `ERROR/INPUT EXPIRED`。
- 未收到 `input_segment_accepted` 时不接受下一次 PTT；确认后下一段使用新的 client input/stream ID，
  由 Host 在同一逻辑轮次内按顺序合并。
- 设备掉电会丢失未确认话语；不把 PCM 写入 Flash。

### 6.2 播放断线

- 断线处理先硬件静音，再清软件 ring，避免残留 DMA 继续发声。
- 连接仍可写时，用户主动 PTT 先发 `playback_cancel`；物理断线时不等待 cancel 发送成功。
- capture 已开始后到达的迟发 `playback_start` 被登记为 discarded stream，终端发送 cancel 并吞掉其
  后续 PCM/end；该竞态是正常抢占，不能升级为协议错误或永久 blocked。
- Host/Runtime 不承诺在新连接回放已经开始的 audio，设备也不自行保存重播。
- 新 epoch 的 `playback_start` 必须建立全新 output/stream；旧 epoch PCM 一律丢弃。

Host 的分段聚合状态属于进程内、设备级易失状态，不属于单条 WSS；普通 WSS 重连不会丢失已确认分段。
Host 进程重启仍会丢失尚未形成 Runtime Input 的聚合轮次，这是 S3.1 明确边界。

## 7. 失败分类

| 分类 | 例子 | 策略 |
|---|---|---|
| Wi-Fi transient | AP 消失、DHCP 失败、IP 变化 | 交给 Wi-Fi Supervisor，拿到 IP 后恢复 |
| Host transient | 无 mDNS、拒绝连接、timeout、1000/1001 close、Host 重启 | Device backoff + 重新发现 |
| service unavailable | `gateway_disabled`、pairing 未开放 | 等 mDNS/Host 状态变化，低频重试 |
| media recoverable | ASR/TTS/audio busy 等 recoverable error | 回 `READY`，不重建连接 |
| certificate blocked | pin 不一致、无 peer cert、Host proof 错误 | `BLOCKED`，不自动信任或重配 |
| identity blocked | 未知身份或签名错误导致的 `authentication_failed` | `BLOCKED`，不自动删除 credential |
| explicit unpair | 在线或签名验证后的离线 `device_revoked` | 清长期身份，保留 Host pin，自动进入未配对扫描 |
| protocol blocked | major 不兼容、坏认证、严格 codec 违规 | 关闭连接并停止快速重试，等待版本/实现修复 |
| duplicate connection | `connection_replaced` | 延迟 30 秒再试；2 分钟内连续 3 次则 `BLOCKED/DUPLICATE` |

`recoverable=false` 不等于全部永久停机，但必须退出当前连接并按错误类别处理，不能统一塞回普通
transient backoff。证书或 active identity 失败不自动清除凭据，避免攻击者诱导设备进入重新配对。

## 8. 并发与风暴控制

- 全局最多一个 DNS query、一个 TCP/TLS handshake 和一个 active WSS。
- timer、Wi-Fi 事件、mDNS 事件同时到达时，通过 Supervisor event queue 合并为一次 connect intent。
- 每个 intent 记录 epoch；过期 intent 不执行。
- 退避加入设备随机 jitter，避免 Host 重启后多设备同时连接。
- heartbeat timeout、socket error 和 close 回调对同一 epoch 只记一次失败、只增加一次 backoff。
- 新认证连接建立前旧连接不再发送应用消息；收到 `connection_replaced` 时执行 duplicate 策略，避免
  两台克隆身份设备互相抢占。

## 9. 诊断指标

普通日志和验收记录至少保留：

- Wi-Fi disconnect/reconnect 次数、当前 IP epoch；
- discovery 次数、Host installation ID 的脱敏后缀；
- TCP/TLS/WSS/auth 尝试、成功、失败和阶段耗时；
- 当前 backoff、连续失败次数、last disconnect reason；
- heartbeat timeout、connection replaced、revoked、pin mismatch 计数；
- pending input bytes、重传次数、等待时长、最终 accepted/expired/cancelled；
- playback 因断线丢弃的 frames/bytes；
- 每 10 次重连后的 internal heap、largest block、PSRAM 和 Network task stack 水位。

不得记录完整 PCM、transcript、配对码、private seed、完整签名或完整设备 ID。

## 10. 验收矩阵

| 场景 | 注入点 | 通过条件 |
|---|---|---|
| AP 关闭/恢复 | idle/listening/processing/speaking | 自动恢复，无重启；各阶段遵守 §6 |
| DHCP/IP 改变 | online | 旧 epoch 作废，重新发现和认证 |
| Host kill/restart | 四个对话阶段 | 保存身份自动认证，不重复输入/重播 |
| Host 端口改变 | idle | 旧 endpoint 失败后重新 mDNS 并恢复 |
| heartbeat 丢失 | online | 30 秒内本地主动断开并进入退避 |
| `listen_stop` 后断线 | ack 前 | 同 ID/同 PCM 重传，只得到同一 Runtime Input/Run |
| accepted 后断线 | processing | 不重传，不创建第二个 Input/Run |
| playback 中断线 | speaking | 立即静音，重连后不重播 |
| pairing 三个掉电点 | hello 后/pending 保存后/commit 后 | 同 request 恢复或 pending auth 激活，无孤儿身份 |
| Host 重启/WSS 开关 | pairing | 显示码不变；有效 attempt 续用，失效窗口重建临时量 |
| TLS pin 改变 | handshake | pin 前无应用数据，进入 `CERT_CHANGED` |
| 在线解除配对 | online | 收到 `device_revoked` 后清身份、静音并进入 `WAIT PAIR` |
| 离线解除配对 | next auth | Host 验签后返回 `device_revoked`，终端自动进入 `WAIT PAIR` |
| generic auth fail | auth | 不清身份、不形成重连风暴，等待用户处理 |
| duplicate identity | online | 30 秒节流，重复 3 次后停止抢占 |
| 20 次 Host 重启循环 | idle | 无 heap/PSRAM 持续下降，最终每次可恢复 |

S3.1 完成前至少执行一次全矩阵；S3.4 再把网络抖动、长时间离线和更多循环纳入严格可靠性验收。
