# 终端操作说明：配对、语音识别与语音播报

本文说明当前正式 `firmware/` 的实际操作方式，覆盖首次配对、重置旧配对、ASR/TTS 配置、
日常对话和连接排查。操作与界面名称于 2026-10-20 核对，桌面界面参考 ez-assistant v0.32.1；
不表示 S3.2 已完成全部实机验收。

## 1. 开始前

- 终端已烧录正式固件，屏幕、外接 PTT 对话键、麦克风、功放和喇叭已按接线基线连接。
- 终端已保存有效的 **2.4 GHz Wi-Fi** 配置，电脑与终端位于可以相互访问的局域网。
- 电脑上的 EZ Assistant 和 Runtime Host 已启动，并登录准备绑定终端的账号。
- 电脑能够访问配置的语音服务；完整对话还需要可用的 Agent 模型和当前主控代理会话。

USB 负责终端供电和串口调试。配对、录音上传和音频下发通过局域网完成，插上 USB 不等于已经
连接到 EZ Assistant。

建议按“配置语音服务 → 开启设备接入 → 配对 → 确认在线 → 实际对话”的顺序操作。

### 1.1 Wi-Fi 网络要求

- 给 ESP32-S3 终端提供 **2.4 GHz** SSID；仅有 5 GHz 的网络不能使用。
- 建议使用 WPA2-Personal 和正常启用 DHCP 的路由器。当前凭据结构只有 SSID 与密码，不包含
  企业 Wi-Fi 的账号、证书或网页认证参数。
- 电脑可以通过网线或其他频段连接同一路由器，但其所在网络必须允许与终端互访和 mDNS 发现。
  访客 Wi-Fi、AP 隔离或跨子网配置可能使设备取得 IP 后仍找不到 Host。
- 按当前实现，SSID 长度为 1～32 UTF-8 bytes；有密码网络的密码为 8～63 bytes。
  中文字符按编码后的字节数计算。

### 1.2 正式固件：已有 Wi-Fi 配置时如何使用

正式固件开机从设备 Flash 的 NVS namespace `wifi_cfg` 读取字符串键 `ssid`、`password`，
然后自动以 Station 模式连接并通过 DHCP 获取 IP。断电后配置保留，不需要每次上电重新录入。

1. 确认原来配置的 Wi-Fi 仍存在，SSID、密码没有改变。
2. 给终端正常上电，等待联网；不要为了联网按住 PTT 触发配对重置。
3. 联网后，再按第 3 节完成 Host 配对或等待原身份自动重连。

需要核对联网进度时，可在仓库根目录先枚举串口，再监控实际端口；第二条命令中的占位路径要替换
为第一条列出的设备端口：

```sh
./firmware/idf.sh ports
./firmware/idf.sh monitor /dev/cu.REPLACE_WITH_ACTUAL_PORT
```

串口打开可能触发 USB 复位，注意第 6.5 节。正式固件中的相关日志用于区分网络状态：

| 日志或现象 | 含义与操作 |
|---|---|
| `event=network_state_changed state=connecting` | 正在连接接入点，等待后续状态 |
| `event=network_ip_acquired state=ready` | 已取得 IP；继续核对 Host，不等于已配对或已在线 |
| `event=network_state_changed state=backoff` | 正在等待重试，检查接入点、密码和信号 |
| 网络状态 `unconfigured`，可能显示 `ERROR / NETWORK` | 没有已保存凭据，需要配网；重置配对不会解决 |
| 网络状态 `error` | 检查凭据读取、Wi-Fi 驱动或存储错误，保留日志再排查 |

暂时掉线后，当前正式固件按 1/2/4/8/16/30 秒上限退避重连；路由器恢复后等待自动连接。
屏幕 `CONNECTING / LOOKING FOR HOST` 还包含寻找 Host 的阶段，不能单凭它判断 Wi-Fi 密码错误。

### 1.3 首次配网或换网络：先确认固件支持的入口

**当前正式 `firmware/` 只有凭据读取，没有串口、屏幕、蓝牙或热点配网入口。**
因此空白设备和需要更改 SSID/密码的正式设备，目前还没有本文可以直接给用户执行的完整配网流程；
需要开发侧补齐正式凭据录入能力或单独制定经过核验的写入方案。不能在没有命令响应时盲目输入
`wifi set`，也不能把整个 NVS 擦除当作配网操作，里面还可能有设备身份。

历史原型确实实现了串口配网，保留于 [`demos/S2.3/main/wifi_manager.c`](../demos/S2.3/main/wifi_manager.c)。
**仅当设备已经运行该类原型固件，且串口明确输出以下提示时，才适用下一节：**

```text
Wi-Fi console ready: wifi set | wifi status | wifi clear
```

本说明不要求将正式设备刷回旧原型。两者应用和分区布局不同，切换、恢复或写入 NVS 前需要另行
核对固件、分区、需保留数据和备份方式，不能把历史命令视为正式固件已经支持的功能。

### 1.4 历史原型的 USB 串口配网步骤

本节只用于已有对应原型固件的设备，不在本文执行烧录或 Flash 擦除。

1. 接入原型的 USB Serial/JTAG 主控制台，关闭其他串口监控程序。
2. 使用 115200 波特率连接实际设备串口，确认出现上一节的命令提示。使用 ESP-IDF 监控器时，
   可在仓库根目录执行 `./demos/S2.3/idf.sh monitor <实际串口>`；按 `Ctrl+]` 退出。
3. 确认准备保存的新 SSID 和密码，输入 `wifi set` 后回车。它会覆盖该设备之前的 Wi-Fi 配置。
4. 在 `SSID>` 提示后输入网络名称，在 `PASSWORD>` 提示后输入密码，分别回车。
   设备不主动回显密码，串口客户端也应关闭本地回显和原始输入录制。
5. 出现 `Credentials saved; connecting` 后等待连接，再输入 `wifi status`。
6. 确认状态为 `connected`、`configured=yes`，且 `ip` 不为空；按需查看 `rssi`、重连计数与
   `last_reason`。这些字段不表示 Host 配对完成。
7. 正常断电重启，确认不再录入凭据也能重新取得 IP。

交互示例仅表示输入顺序，SSID 和密码都需在本地换成自己的真实值；不要把示例原样发送到设备：

```text
wifi set
SSID> YOUR_2_4_GHZ_SSID
PASSWORD> YOUR_WIFI_PASSWORD
Credentials saved; connecting
wifi status
```

历史命令作用如下：

| 命令 | 作用 |
|---|---|
| `wifi set` | 依次录入 SSID 和密码，写入 `wifi_cfg`，然后连接；换网络时同样使用此命令 |
| `wifi status` | 读取连接状态、IP、RSSI 和计数，不输出密码 |
| `wifi clear` | 删除该 namespace 的 Wi-Fi 配置；确认需要删除后才执行，之后需要重新配网 |

SSID、密码保存在设备本地，与电脑 ASR/TTS 的 `config.toml` 和 API Key 无关。
**重置配对会保留 Wi-Fi，不能用来更换网络。** Wi-Fi 密码同样不进入仓库、聊天或截图；
不要把当前开发板的 NVS 存储视为已具备量产级加密和物理防护。

## 2. 配置语音识别与语音播报

ASR 将终端录音转换成文字；TTS 将 Agent 提交的播报文本合成为音频。两者由电脑上的 Runtime
Host 调用，配置保存在电脑上。

当前界面的“语音服务”区域只显示状态，尚无 Provider、模型、声音和 API Key 的编辑表单，
需要编辑当前账号的 `config.toml`。

### 2.1 找到当前账号实际使用的文件

1. 打开 EZ Assistant 的“账号与 Runtime”菜单，进入 **设置 → Runtime → 状态与诊断**。
2. 在“诊断信息”中找到 `config.toml` 的完整路径，以这里显示的路径为准。
3. 在运行该 Host 的电脑上编辑这个文件；连接远程 Host 时，编辑远端文件。

目前常见目录结构如下，`<Runtime Home>` 通常为 `~/.ez-assistant`，也可能由启动参数另行指定：

| 环境 | 常见配置位置 |
|---|---|
| 个人环境 | `<Runtime Home>/users/_personal/config.toml` |
| 登录企业账号 | `<Runtime Home>/users/<center_id>_<user_id>/config.toml` |

**切换账号后必须重新核对路径。** 个人环境中的语音配置不会自动成为当前企业账号的配置；
Host 根目录的 `host.toml` 也不是这里要编辑的用户语音配置。

### 2.2 填写 ASR/TTS 配置

文件不存在时，新建文件并使用下面的结构。文件已存在时，先在本机保留原文件副本，再合并
两段语音配置；保留已有的其他配置。`schema_version = 1` 应位于文件顶层，整份文件只写一次，
同名 `[speech.asr]`、`[speech.tts]` 表也只能各有一份。

```toml
schema_version = 1

[speech.asr]
provider = "dashscope"
model = "qwen-audio-3.0-asr-flash"
credential = "REPLACE_WITH_DASHSCOPE_API_KEY"
endpoint = "https://dashscope.aliyuncs.com"
timeout_ms = 30000

[speech.tts]
provider = "dashscope"
model = "qwen-audio-3.0-tts-flash"
voice = "longanyuanfei"
credential = "REPLACE_WITH_DASHSCOPE_API_KEY"
endpoint = "https://dashscope.aliyuncs.com"
timeout_ms = 30000
```

上面的模型和音色沿用本次已被本地 Host 成功加载的配置，并非服务商模型目录或真实调用成功的
保证。使用前确认自己的 DashScope 账号、地域端点、模型权限和音色支持情况，并替换两处
`credential` 占位符。ASR/TTS 可以使用同一把有相应权限的 Key，也可以分别配置。

| 字段 | 用途与当前约束 |
|---|---|
| `provider` | 当前实现支持 `dashscope`，按此拼写填写 |
| `model` | 对应能力的模型 ID，须与当前 Adapter 请求接口兼容 |
| `voice` | 仅 TTS 必填，填写该 TTS 模型支持的音色 |
| `credential` | API Key；必填，不能留空或带首尾空白 |
| `endpoint` | 服务根地址；省略时为上述 DashScope 地址，不填写具体 API 路径 |
| `timeout_ms` | 单次请求超时，单位毫秒；省略时为 30000，允许 1～120000 |

仅在本地安全编辑器中填写真实 API Key，不把配置文件放入本仓库、聊天或截图。macOS/Linux
上将实际配置文件权限设为 `600`，目录权限设为 `700`；执行权限命令时使用诊断页确认的真实路径。

如果原个人环境已经有可用配置，可以仅复制其中 `[speech.asr]` 和 `[speech.tts]` 两段到目标账号
文件，再核对该账号是否应使用原来的 API Key、模型和声音。

### 2.3 重新加载并确认生效

1. 保存文件。
2. 在 **设置 → Runtime → 状态与诊断** 点击 **重新加载配置**。
3. 确认出现“配置已重新加载”，配置状态为“可用”。
4. 打开 **设置 → 智能终端**，必要时点击 **刷新**。
5. 确认“语音识别”和“语音播放”都显示 **可用**。

“刷新”只重新读取界面状态，不能代替“重新加载配置”。一般无需重启 Host 或再次配对。
已经处于重试中的终端会重新尝试连接；若已在线连接的协商能力仍为旧值，可在空闲时普通重启
终端一次，保留配对，建立新连接。

| 界面状态 | 含义 |
|---|---|
| 可用 | 配置已被本地加载，可以接纳该能力的请求 |
| 部分可用 | 子系统仍在运行，最近请求或任务出现异常，需要结合实际调用排查 |
| 不可用 | 缺少配置、字段非法或 Provider 无法构造，先核对路径与配置 |

**“可用”不代表 Key、模型权限和扬声器已经通过真实调用验证。** 填入格式正确的占位 Key 也不能
证明服务可用；最后必须执行第 5 节的录音和实听检查。真实语音及 Agent 请求会按所配置服务计费。

## 3. 首次配对

1. 在目标账号的 **设置 → 智能终端** 中开启 **设备接入**。
2. 点击 **添加设备**。界面显示“正在等待终端发起配对…”，进入约 5 分钟的配对窗口。
3. 给已配置 Wi-Fi 的终端上电。未配对终端会自动扫描可接入的 Host，无需按 PTT 发起配对。
4. 查看终端屏幕上的 **6 位配对码**。桌面出现 `Agent Robot Terminal` 候选后，在其“配对码”
   输入框填写屏幕上的数字，点击 **确认配对**。
5. 等待设备出现在“已配对设备”中。配对完成后终端还会重新建立连接并认证，随后桌面应显示
   **在线**；点击设备名称可查看本次连接的能力和输出偏好。

“已配对设备”数量增加，只表示身份登记完成，不等于已经在线或可以对话。需要分别确认
**已配对、在线、语音识别可用、语音播放可用**。

如果配对窗口过期，重新点击“添加设备”。同一局域网有多台 EZ Assistant 时，只在准备绑定的
那一台开放添加窗口，避免终端遇到多个可配对 Host。

配对完成后，日常插拔终端、重启原 Host 或关闭再开启设备接入，通常会使用已保存身份自动重连，
不需要反复添加设备。

## 4. 更换 Host 或账号：手动重置配对

终端保存了之前绑定的 Host 身份。重装应用、改用另一份 Runtime Home、切换账号或更换电脑后，
如果 Host 身份发生变化，终端不会自动改绑到新 Host；旧身份仍在时也不会作为新设备申请配对。

确认需要放弃旧绑定后，使用以下设备侧操作。它会清除终端的配对身份和 Host 绑定，**保留 Wi-Fi**，
不删除原 Host 上的历史会话；原 Host 的设备登记不会由此自动移除。

1. 将终端断电。
2. **先按住外接 PTT 对话键（GPIO21）**。这是平时按住说话的按键，不是开发板的 BOOT 或 RST。
3. 保持按住，重新接通电源。
4. 持续按住约 **8 秒**，以屏幕出现 **RELEASE TO RESET** 为准。
5. **看到提示后松开按键**。终端此时才清除配对并自动重启；一直按住不会执行清除。
6. 在目标账号重新执行第 3 节的添加和配对操作。

### 为什么不与对话冲突

| 按键时机 | 行为 |
|---|---|
| 启动时已按住，持续约 8 秒，出现提示后松开 | 重置配对 |
| 正常运行后按下并保持 | 开始并保持本次录音，松开结束；不会因超过 8 秒而清配对 |
| 播报过程中按下 | 抢占当前播报，进入新的输入流程 |

重置检测仅在启动阶段执行一次。**开机以后再长按，即使超过 8 秒也不会触发重置。**
如果按住再上电仍没有提示，先确认使用的是 GPIO21 外接按键、接线有效，并确认实机确实运行
包含该功能的正式固件。

桌面“解除配对”用于撤销该 Host 上的设备登记，与终端本地重置是不同操作。旧 Host 已不可用或
终端仍寻找旧 Host 时，使用上述本地重置流程。

## 5. 日常对话与最小验证

开始前确认桌面设备显示“在线”，两项语音服务均为“可用”。在 EZ Assistant 中准备可用的模型和
当前主控代理会话；终端输入由 Host 路由到该主控会话。

1. 按住 PTT 对话键，清楚说一句：“请用语音回答：你好，设备测试。”
2. 说完松开，等待识别和 Agent 处理。当前为整句识别，不要求说话过程中逐字显示结果。
3. 在主控会话中核对本次输入的识别内容，确认只提交了一次。
4. 实际听完回复，检查内容、音量和完整性。
5. 播报期间再按下 PTT，确认旧播报停止，新一句可以正常输入。

语音回复由主控 Agent 的 `speak` 播报流程提交给 TTS。普通 Assistant 文字正文不会自动全部朗读；
有文字回复但没有声音时，要同时检查是否实际产生了播报请求。

当前正式固件主要使用 PTT，空闲态 WakeNet 尚未接回正式链路。播放时按 PTT 打断可用；
播放中直接说话打断不属于当前操作方式。

## 6. 常见问题

### 6.1 配对成功后一直显示 CONNECTING

按以下顺序排查，先保留现有配对：

1. 查看桌面设备是“在线”还是“离线”，不要只看终端屏幕。
2. 查看 **设置 → 智能终端 → 语音服务**，尤其确认“语音播放”是否可用。
3. 若 TTS 不可用，按第 2 节核对当前账号的配置文件并重新加载。
4. 两项语音服务已可用但仍离线时，检查 Wi-Fi、Host 运行状态、设备接入开关、局域网发现和
   认证错误。
5. 若已确认更换了 Host 身份且旧绑定仍在，再按第 4 节手动重置。

当前固件连接时请求音频输出。Host 的 TTS 不可用时，会在握手阶段拒绝不支持的输出偏好，终端
继续退避重试，因此可能出现“配对已成功但始终 CONNECTING”。ASR 单独不可用则会影响语音输入，
也必须配置，不能只以设备在线作为完成依据。

如果桌面已经显示在线，终端屏幕却仍停在 CONNECTING，应记录屏幕和桌面状态并排查终端 UI
投影；当前源码中配对完成状态的显示优先级也可能遮住在线状态。可在空闲时普通断电重启一次
核对恢复情况，重启时不要按住 PTT，也不要为了修复显示反复清除配对。

### 6.2 桌面一直等待终端发起配对

- 确认终端已有有效 Wi-Fi 配置，电脑和终端在允许互访的网络中。
- 确认目标 Host 开启“设备接入”，且“添加设备”窗口没有过期。
- 检查终端是否还保存旧绑定；已经配对的终端只会选择与已保存身份匹配的 Host。
- 确认没有同时开放多个 Host 的配对窗口。
- 检查访客 Wi-Fi、AP 隔离或防火墙是否阻止局域网 mDNS 发现及设备 WSS 连接。排查具体规则，
  不需要关闭整个防火墙。

设备发现服务为 `_ez-assistant._tcp.local.`，Host 的设备 WSS 端口由服务发现提供，不要把
桌面连接 Host 的 7240 端口直接当作设备网关端口。

### 6.3 修改配置后仍显示语音服务不可用

- 再次核对“状态与诊断”里的当前配置路径；尤其检查是否只改了个人环境或另一个账号。
- 检查 TOML 语法、重复表、顶层 `schema_version` 和当前支持的字段。
- 确认 `provider = "dashscope"`，模型和 Key 非空，TTS 额外填写了 `voice`。
- 点击“重新加载配置”后再回到智能终端页刷新。ASR/TTS 独立加载，一侧配置错误可能只影响一侧。

### 6.4 在线但不能识别，或有回复却听不到声音

- “可用”只是本地配置状态；核对真实请求是否遇到 Key 无效、权限不足、模型/音色不兼容、网络
  或超时错误。不要把反复配对作为 Provider 故障的修复办法。
- 不能识别时，检查 PTT 录音动作、麦克风及是否出现有效转写。
- 有转写但没有正常处理时，检查主控代理会话、Agent 模型和必要的桌面审批提示。
- 有文字但没有播报请求时，检查主控 Agent 的 `speak` 路径；已有播报请求则继续核对 TTS 结果、
  设备在线连接、功放和喇叭接线，并实际试听。

### 6.5 需要串口诊断

端口名称随电脑和 USB 接口变化，以实际枚举结果为准。一个串口同时只能由一个监控程序使用。
采集器不会主动发送复位命令，但本次 macOS USB 串口建立或重新建立连接时，观察到
`USB_UART_CHIP_RESET`，因此不能保证打开串口完全不影响运行。

需要对照故障发生前后的行为时，先开始采集，再复现问题；不要用连接串口后重启恢复的状态代替
故障现场。脱敏采集方式见 [`firmware/README.md`](../firmware/README.md) 和
[`S3.2 人工验收`](versions/S3.2/人工验收.md)。
